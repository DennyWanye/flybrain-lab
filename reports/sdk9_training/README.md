# SDK9 果蝇模拟训练：首次运行交付

日期：2026-09-26。范围：把三维模拟器接入可训练的果蝇控制链，完成一次有限预算的真实训练，并保存可核查结果。

**训练链路已跑通；模型尚未学会任务。MODEL_READY_FOR_NEXT_STAGE = false。**

## 已实现

- 测量观测 26 维 → 34 个非负编码通道 → 冻结 MaleCNS 神经网络 → 128 维膜电位/迹特征 → PPO actor/critic → SDK 动作 → 与三维沙盒共用的 MuJoCo 执行器。
- 保留真实连接图的 166700 个节点、25582938 条边；本阶段只训练读出层，不训练连接图权重。策略与价值网络不直接接收原始观测或物理真值。
- 9 动作协议：停止、前后左右上下各 20 cm、左右转各 30 度。C0 课程仅开放停止与平面四向移动；起飞由任务管理器完成。
- 外部定位模拟包含采样编号、坐标系、时效、噪声、延迟和丢帧；速度从测量位置估计。真值用于奖励/终止判定及展示。未来实机需要适配相同定位语义。
- 动作按实际持续时间计价：每 0.1 秒采样一次，每次推进 4 个脑子步；每个动作记录 R、Gamma=0.995^k、终止/截断和所用动作掩码。
- 检查点绑定图、映射、世界配置、版本与输入动作契约；格式不匹配拒绝加载。支持推理及显式 warm-start；不支持原地精确恢复训练。warm-start 重置优化器与环境状态，并记录来源。
- 保存训练、规则基线、初始模型、训练后模型、故障诊断的轨迹、神经活动、观测和指令记录；查看器读取相同产物，不推进训练时钟。
- 实机设备适配器明确禁用，本轮没有给任何真实无人机发送指令。

首次 128 动作尝试在基线阶段遇到规则控制 3/4 成功，程序自动拒绝训练。诊断发现速度限制计算偏保守。修正共用低层控制器，并将世界配置设置为 position_kp=2.0、velocity_kd=2.4 后，同样 4 个场景为 4/4；原失败场景 35.6 秒成功。没有放宽 60 秒期限、20 cm 目标半径或 2 秒稳定保持条件。旧失败记录保留在 pilot.log 及原运行目录。

## 运行与复用

在 WSL Ubuntu-24.04 的项目根目录运行（输出目录必须为空/全新）：

```bash
/home/denny/projects/flybrain-env/bin/python -m flydrone.tellosim.training.runner \
  --graph data/male-v1.npz --device cuda \
  --out runs/tellosim-sdk9/new-experiment \
  --options 128 --rollout 32 --eval-cases 4
```

`--init-from runs/tellosim-sdk9/sdk9-pilot-v2-20260926/checkpoint.pt` 是显式 warm-start，不是精确续训。世界或契约变更需要新实验，旧 checkpoint 会被兼容检查拒绝。恢复推理可使用 `ReservoirAgent` 与 `load_checkpoint`；设备协议位于 `training/contracts.py`，环境 reset/advance 不属于可迁移设备接口。

建议下一阶段先诊断神经特征是否保留目标方向、为什么策略收敛到停止，设定多种子的小预算对照和课程，再增加训练预算。现有证据不支持把耗时仅归因于训练次数不足。继续美化三维房间不是当前优先项。

物理参数和电池模型为工程假设，未对真实 Tello 标定。当前可复用的是观测/动作契约、共享执行器、冻结脑特征和训练/评估流水线，不能宣称已交付可用的飞行策略。
